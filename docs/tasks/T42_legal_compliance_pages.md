# T42. 법적 고지 페이지 및 동의 흐름 구현

- 상태:
  진행 전

- GitHub Issue:
  161

- 우선순위:
  P1

- 선행 조건:
  - 선행 task: T44. 판매자 신분증 원본 처리 및 KYC 보관 정책 결정
  - 선행 task: T61. 판매자 신청 서류에서 신분증 타입 완전 제거 (판매자 신청 동의 흐름 구현 전 코드/DB 기준 정리)

- 분류:
  법적 준수

- 사용자 흐름:
  Shared

- 주 담당 역할:
  Domain

- 보조 역할:
  Architecture

- 배경:
  개인정보보호법(PIPA) 및 전자상거래법상 개인정보처리방침 공개, 이용약관 공개, 정보주체 동의 수집이 법적 의무다. 현재 고지 페이지와 가입/서류 제출 동의 흐름이 없어 법적 리스크가 있다. 법적 의무 항목 상세: `docs/legal_compliance.md`

- 문제:
  개인정보처리방침·이용약관 페이지 미구현, 회원가입 동의 체크박스 미구현, 판매자 서류 제출 시 민감정보 별도 동의 미구현.

- 작업 내용:
  **고지 페이지**
  - `/privacy-policy` 페이지: 개인정보처리방침 내용 표시. 필수 항목은 `docs/legal_compliance.md` 섹션 3 참조.
  - `/terms` 페이지: 이용약관 내용 표시.
  - Footer에 두 페이지 링크 추가.

  **회원가입 동의 흐름**
  - 이용약관 동의 (필수)
  - 개인정보 수집·이용 동의 (필수)
  - 마케팅 수신 동의 (선택, 독립 체크박스)
  - 전체 동의 체크박스 제공 (필수 항목만 일괄 선택 or 전체 선택)

  **판매자 신청 동의 흐름**
  - 서류 업로드 단계에서 판매자 심사용 서류 수집·이용 동의 (PIPA 제15조·22조, 필수)
  - 대상: 사업자등록증, 영업신고증, 통장사본 3종
  - T44 결정으로 신분증 제거 → PIPA 제23·24조 민감정보·고유식별정보 별도 동의는 불필요
  - 회원가입 일반 개인정보 동의와 별도 독립 체크박스로 구분

- 관련 파일/영역:
  - `src/app/privacy-policy/page.tsx` (신규)
  - `src/app/terms/page.tsx` (신규)
  - `src/components/layout/Footer.tsx` (또는 기존 Footer 컴포넌트 수정)
  - `src/app/auth/` 가입 화면 (동의 체크박스 추가)
  - `src/app/(seller)/seller/register/` 판매자 신청 서류 단계 (민감정보 동의 추가)

- 예상 난이도:
  중간

- 완료 기준:
  - `/privacy-policy`, `/terms` 페이지가 공개 접근 가능하고 법적 필수 항목을 포함한다.
  - Footer에 두 페이지 링크가 노출된다.
  - 회원가입 시 필수/선택 동의 체크박스가 구분되고, 미동의 시 가입이 차단된다.
  - 판매자 신청 서류 제출 단계에서 3종 서류 수집·이용 동의가 존재하고, 미동의 시 제출이 차단된다.
