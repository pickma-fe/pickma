# T58. 관리자 대시보드 통계 화면 구현

- 상태:
  완료

- GitHub Issue:
  239

- 우선순위:
  P1

- 선행 조건:
  - 선행 task: T07 (service role 사용 기준 및 owner scope 테스트 수립)

- 분류:
  화면/UI

- 사용자 흐름:
  Admin

- 주 담당 역할:
  Frontend

- 보조 역할:
  API

- 배경:
  현재 `/admin` 페이지는 판매자 승인과 전체 가게 링크 카드만 제공하는 메뉴 허브 수준이다. PRD A-DASH-01은 총 가게수, 총 상품수, 총 주문수, 총 사용자수 통계를 P1 요구사항으로 정의하지만 이를 구현하는 task가 없어 T58로 등록한다.

- 문제:
  관리자 대시보드에 플랫폼 통계가 없어 운영 현황을 한눈에 파악할 수 없다.

- 작업 내용:
  - `/admin` 페이지를 통계 대시보드로 확장
    - 총 가게수, 총 상품수, 총 주문수, 총 사용자수 summary 카드
    - PRD A-DASH-01 완료 기준 충족
  - 통계 집계 API 구현 (관리자 전용)
  - 기존 판매자 승인/가게 목록 링크 카드 유지 또는 네비게이션으로 이동

- 관련 파일/영역:
  - `src/app/(admin)/admin/page.tsx`
  - `src/app/api/admin/dashboard/` (통계 집계 API)

- 예상 난이도:
  보통

- 완료 기준:
  - `/admin` 진입 시 총 가게수, 총 상품수, 총 주문수, 총 사용자수 통계 카드가 렌더링된다.
  - 관리자 권한이 없는 사용자는 접근 불가 처리된다.
  - PRD A-DASH-01 요구사항을 충족한다.

- 확인 필요 사항:
  - 통계 집계 API는 실시간 count 방식으로 구현한다.
  - 기존 판매자 승인/가게 목록 이동은 관리자 사이드 네비게이션으로 유지한다.

- 구현 결과:
  - `/admin` 페이지를 플랫폼 통계 대시보드로 확장했다.
  - `GET /api/admin/dashboard/stats` 관리자 전용 통계 API를 구현했다.
  - 총 가게수, 총 상품수, 총 주문수, 총 사용자수 summary 카드를 렌더링한다.
  - 최근 7일 주문/매출 현황과 최근 승인 대기, 최근 주문, 신규 사용자 섹션을 렌더링한다.
  - 최근 승인 대기 섹션은 요약 정보만 제공하고, 실제 승인/거절은 `/admin/sellers/pending` 심사 화면으로 이동해 처리하도록 연결했다.
  - 공지사항은 현재 공지 도메인/API가 없어 T58 범위에서 제외하고 후속 공지 도메인 task에서 연동한다.
  - mock/real mode 모두 Route Handler에서 `requireAdmin()`을 통과하도록 고정했다.
  - service/route 테스트로 count 집계와 관리자 권한 검증을 확인했다.
