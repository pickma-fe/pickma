# 1. 개요 (Overview)

## 1.1 제품 소개

**픽마(PickMa)**는 마감 임박 상품을 할인된 가격에 예약하고, 지정된 시간에 픽업할 수 있는 웹 플랫폼입니다.

## 1.2 목적

- 판매자: 폐기 예정 상품의 손실을 줄이고 추가 수익 창출
- 소비자: 할인된 가격으로 상품 구매 기회 제공
- 사회적: 음식물 폐기 감소를 통한 환경 보호 기여

## 1.3 프로젝트 범위

- **기간**: 2026.04.20 (월) ~ 05.21 (목)
- **범위**: MVP 기능 구현 (상품 조회, 예약, 결제, 픽업)

# 2. 사용자 정의 (User Definition)

## 2.1 사용자 유형

| 유형                       | 설명                                      | 가입 방식                          |
| -------------------------- | ----------------------------------------- | ---------------------------------- |
| **일반 사용자 (Customer)** | 상품을 조회하고 예약/구매하는 소비자      | 이메일 또는 소셜 로그인            |
| **판매자 (Seller)**        | 마감 상품을 등록하고 판매하는 가게 사장님 | 별도 판매자 회원가입 → 관리자 승인 |
| **관리자 (Admin)**         | 플랫폼 전체를 관리하는 운영자             | 시스템 계정                        |

## 2.2 사용자 페르소나

**👤 일반 사용자 - 김절약 (28세, 직장인)**

- 퇴근 후 저렴하게 저녁거리를 구매하고 싶음
- 앱으로 미리 예약하고 바로 픽업하길 원함
- 가성비 좋은 상품을 찾는 것이 목표

**👤 판매자 - 박사장 (45세, 베이커리 운영)**

- 매일 저녁 남는 빵 폐기로 손실 발생
- 마감 시간 전 할인 판매로 손실을 줄이고 싶음
- 간편하게 상품 등록하고 예약 관리하길 원함

# 6. 주요 비즈니스 로직

## 6.1 사용자 → 판매자 전환 흐름

```
[소셜 로그인] → [일반 사용자] → [판매자 신청] → [관리자 승인] → [판매자] → [가게 등록]
(사업자 정보 + 필수 서류)
```

> **Note**: 판매자 승인과 가게 등록은 분리한다. 승인된 판매자는 MVP 기준 1개 가게를 등록할 수 있다.

## 6.2 주문 상태 흐름

```
[결제대기] → [예약완료] → [픽업대기] → [픽업완료]
    ↓            ↓          ↓
[결제만료]     [취소됨]      [노쇼]
```

| 상태                           | 설명                            | 전이 조건                  |
| ------------------------------ | ------------------------------- | -------------------------- |
| **결제대기 (PAYMENT_PENDING)** | 주문 생성, 결제 전 대기         | 상품 예약 생성 시          |
| **예약완료 (RESERVED)**        | 결제 완료, 접수 대기            | 결제 성공 시               |
| **준비 중 (ACCEPTED)**         | 판매자 접수, 상품 준비 중       | 판매자가 접수 처리 시      |
| **준비완료 (READY)**           | 상품 준비 완료, 픽업 가능       | 판매자가 준비 완료 처리 시 |
| **픽업완료 (COMPLETED)**       | 고객이 상품 수령                | 판매자가 완료 처리         |
| **취소됨 (CANCELLED)**         | 주문 취소                       | 사용자 취소 요청           |
| **노쇼 (NO_SHOW)**             | 미픽업                          | 판매자가 노쇼 처리         |
| **결제만료 (EXPIRED)**         | 결제 가능 시간이 지나 주문 만료 | 결제 제한 시간 초과        |

### 6.2.1 주문번호 및 픽업번호

- `orderNumber`는 PickMa의 전역 주문번호이며 PG 결제 요청의 주문 ID 필드에 매핑한다.
- `orderNumber`는 주문 생성 시점에 발급하고, 결제 성공/실패/만료와 무관하게 변경하지 않는다.
- `storeOrderNumber`는 결제 완료 후 판매자 주문 관리용으로 발급한다.
- `pickupNumber`는 결제 완료 후 현장 픽업 확인용으로 발급한다.
- `storeOrderNumber`와 `pickupNumber`는 매장+픽업일 기준 결제 완료 순서에서 생성하며, 취소/환불/노쇼가 발생해도 회수하거나 재사용하지 않는다.
- 결제 대기 또는 결제 만료 주문에는 `storeOrderNumber`와 `pickupNumber`를 부여하지 않는다.

## 6.3 판매자 승인 흐름

```text
[신청] → [심사중] → [판매자 승인] → [가게 등록] → [운영중]
  ↓
[거절됨] → [재신청]
```

## 6.4 상품 마감 로직

- 마감 시간 도달 시 자동으로 상품 비노출 처리
- 재고 소진 시 즉시 품절 처리
- 판매자가 수동으로 조기 마감 가능

| **판매자 주문번호**      | 결제 완료 후 매장 주문 관리를 위해 발급되는 매장+픽업일 기준 순번       |
| **픽업번호**             | 결제 완료 후 고객과 매장이 현장에서 픽업을 확인할 때 사용하는 짧은 번호 |
| **노쇼 (No-Show)**       | 예약 후 픽업 시간에 나타나지 않는 것                                    |
| **PG (Payment Gateway)** | 온라인 결제 대행 서비스                                                 |
| **OAuth**                | 소셜 로그인을 위한 인증 프로토콜                                        |

# 9. 제약 사항 및 가정

## 9.1 제약 사항

- 자체 회원가입 없이 **소셜 로그인(Google, Kakao)만 지원**
- 승인된 판매자는 MVP 기준 가게 1개만 등록 가능
- 기본 프로젝트에서는 지도 기반 위치 조회 미구현 (심화에서 구현)
- 실시간 알림 기능 미구현 (심화에서 구현)
- 리뷰/평점 기능 미구현

## 9.2 가정

- 사용자는 Google 또는 Kakao 계정을 보유하고 있음
- 사용자는 스마트폰 또는 PC에서 웹 브라우저를 통해 접속
- 판매자는 사업자등록증을 보유한 정상 영업 중인 가게
- PG 결제 연동은 테스트 환경으로 구현 (실결제 X)
